## Project

Data Vault is a platform for viewing data charts online. The repo is at the `create-next-app` starter stage: `app/page.tsx` and the metadata in `app/layout.tsx` are still template placeholders, and no product code exists yet.

Development follows Spec Driven Design using the `/spec` and `/spec-impl` skills from [Klerith/fernando-skills](https://github.com/Klerith/fernando-skills). The skills are not checked in. Install them with:

```bash
npx skills@latest add Klerith/fernando-skills
```

## Commands

```bash
npm run dev                        # Dev server at http://localhost:3000
npm run build                      # Production build
npm run start                      # Serve the production build
npm run lint                       # ESLint over the whole repo
npx eslint app/page.tsx            # Lint a single file
npx next typegen && npx tsc --noEmit   # Type check (no npm script exists for this)
```

No test framework is configured, so there is no test command.

## Architecture

Next.js 16 App Router with React 19, strict TypeScript, and Tailwind CSS v4. Routes live in `app/` at the repo root (there is no `src/`). The `@/*` path alias maps to the repo root.

Settings in `next.config.ts` that shape how code must be written:

- **`cacheComponents: true`**: data fetching is dynamic by default, and caching is opt-in per page, component, or function with `use cache` and `cacheLife`. Routes are served as a prerendered static shell with dynamic content streaming in. Read `node_modules/next/dist/docs/01-app/01-getting-started/08-caching.md` before adding data fetching.
- **`partialPrefetching: true`**: `<Link>` prefetches a route's App Shell by default rather than the full page. Automatic prefetching does not run in `next dev`, so check prefetch behavior against a production build.
- **`experimental.agentFeedback: true`**: `next dev` manages blocks inside `AGENTS.md` and restores them if removed. Commit those changes rather than reverting them.

Tailwind is wired through the `@tailwindcss/turbopack` loader in `turbopack.rules`, not PostCSS, so there is no `postcss.config` or `tailwind.config` file. Theme tokens are defined with `@theme inline` in `app/globals.css`, and dark mode follows `prefers-color-scheme`.

`LayoutProps` and `PageProps` are global types generated by Next.js from the route tree into `.next/`, and `next-env.d.ts` is gitignored. On a fresh checkout, type checking fails until `next typegen`, `next dev`, or `next build` has run.
