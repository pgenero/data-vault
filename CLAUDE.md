## Project

Data Vault is a platform for viewing data charts online. The only page so far is the home page in `app/page.tsx`, whose sample panel uses made-up data from `app/_data/sample-traffic.ts`. There are no real panels or data sources yet.

Development follows Spec Driven Design using the `/spec` and `/spec-impl` skills from [Klerith/fernando-skills](https://github.com/Klerith/fernando-skills). The skills are not checked in. Install them with:

```bash
npx skills@latest add Klerith/fernando-skills
```

## Architecture

Next.js 16 App Router with React 19, strict TypeScript, and Tailwind CSS v4. Routes live in `app/` at the repo root (there is no `src/`). The `@/*` path alias maps to the repo root.

Settings in `next.config.ts` that shape how code must be written:

- **`cacheComponents: true`**: data fetching is dynamic by default, and caching is opt-in per page, component, or function with `use cache` and `cacheLife`. Routes are served as a prerendered static shell with dynamic content streaming in. Read `node_modules/next/dist/docs/01-app/01-getting-started/08-caching.md` before adding data fetching.
- **`partialPrefetching: true`**: `<Link>` prefetches a route's App Shell by default rather than the full page. Automatic prefetching does not run in `next dev`, so check prefetch behavior against a production build.
- **`experimental.agentFeedback: true`**: `next dev` manages blocks inside `AGENTS.md` and restores them if removed. Commit those changes rather than reverting them.

Tailwind is wired through the `@tailwindcss/turbopack` loader in `turbopack.rules`, not PostCSS, so there is no `postcss.config` or `tailwind.config` file. Theme tokens are defined with `@theme inline` in `app/globals.css`. The theme is dark-only, so don't use `dark:` variants. Its header comment sets the rules for glow, neon and the three typefaces; chart colors come only from the `--series-*`, `--seq-*`, `--div-*` and status tokens.

`LayoutProps` and `PageProps` are global types generated by Next.js from the route tree into `.next/`, and `next-env.d.ts` is gitignored. On a fresh checkout, type checking fails until `next typegen`, `next dev`, or `next build` has run.

# Mandatory Project Instructions (Power BI & TMDL Safeguards)

## Golden Rule Against Raw Code Fallbacks
* **STRICTLY PROHIBITED:** Do not manually edit, modify, or rewrite Power BI metadata files (`.tmdl`, `.bim`, `.pbi`, or model folders) using generic text-editing tools (such as `write_to_file`, `edit_file`, or line replacements).
* Every single change regarding DAX measures, table relationships, or semantic model structures **MUST** be executed exclusively by invoking the tools provided by the `powerbi-modeling-mcp` server.

## Operational Protocol
1. When asked to create, update, or optimize a DAX measure, you must first utilize the MCP server tools to inspect the current state of the model.
2. Apply structural adjustments solely through the Model Context Protocol (MCP) server endpoints connected to Power BI.
3. If the action requested is unsupported by the MCP server or if the server goes offline, **STOP immediately** and alert the user. Do not attempt to fallback into editing the raw TMDL or BIM files as text.
